# Запланировано: обновление WB из UI и отображение версии пакета

**Статус:** отложено, не реализовано.  
**Репозитории:** `wb.update`, `wb.srv`, `wb.ui`.  
**Точка входа:** страница «Информация», блок «Прибор».

## Цель

Дать пользователю возможность увидеть версию фактически установленного пакета WB и обновить прибор одной кнопкой непосредственно из UI — без SSH, терминала и ручного скачивания `.wbpkg`.

## 1. Версия установленного пакета

Добавить в блок «Прибор» строку вида `WB 0.2.14` рядом с существующими UI, API и FW.

- Версию брать из **фактически установленного** `manifest.json`, не из последнего GitHub Release и не выводить из версий компонентов.
- При установке сохранять версию, дату установки и сведения о компонентах в постоянных метаданных; прежде проверить, не сохраняется ли manifest уже сейчас. Возможный путь: `/opt/wb.srv/package-version.json`.
- Выдавать данные через API `wb.srv`.
- Если версия неизвестна (старая установка), показывать `WB —`, не угадывать.
- После обновления показывать новую версию.

## 2. Проверка обновлений

Кнопка «Проверить обновления» рядом с версией WB.

1. Сервер обращается к GitHub Releases `an2an1970/wb.update`.
2. Выбирает последний опубликованный стабильный релиз с подходящим `.wbpkg` (не draft и не prerelease).
3. Сравнивает его версию с установленной.
4. UI показывает «Актуальная версия», «Доступно обновление», ошибку проверки или неизвестную локальную версию.

При наличии обновления показывать номер, краткий changelog из Release и кнопку «Установить».

## 3. Обновление одной кнопкой

После «Установить» показать явное подтверждение, что работа прибора прервётся и потребуется перезагрузка.

1. Проверить, что эксперимент не выполняется и прибор безопасно обновлять.
2. Проверить свободное место.
3. Скачать `.wbpkg` во временный каталог.
4. Проверить целостность, совместимость и подлинность пакета. **Встроенные SHA-256 подтверждают целостность, но не подлинность.** Предусмотреть криптографическую подпись релизов; до её внедрения использовать только доверенный источник HTTPS и проверку ожидаемого релиза, не выдавая это за эквивалент подписи.
5. Запустить существующий установщик `wb.update` без дублирования прошивки, резервного копирования и rollback.
6. По завершении — штатная перезагрузка.

## 4. Архитектура

### wb.update

- Сохранять метаданные установленной версии.
- Создать независимый системный сервис обновления с необходимыми правами, переживающий остановку Java-сервера.
- Реализовать скачивание, верификацию, запуск штатного установщика, журнал и постоянное состояние операции.

### wb.srv

- API установленной версии, проверки релизов, запуска обновления и чтения состояния.
- Проверка режима прибора и отсутствия активного эксперимента.
- Связь с ограниченным системным сервисом обновления.

### wb.ui

- Строка WB-версии на странице «Информация».
- Кнопка проверки обновлений, changelog, подтверждение установки, прогресс и сообщения об ошибках.

**Не запускать установщик внутри процесса `wb.srv`:** штатная установка останавливает `wb-srv.service`. Не предоставлять UI произвольный shell/sudo-доступ; системный сервис выполняет только строго разрешённые операции.

## 5. Состояния, устойчивость, ошибки

Предусмотреть: проверка, нет обновлений, доступно обновление, скачивание с прогрессом, проверка пакета, установка, ожидание перезагрузки, завершено, ошибка.

- Хранить состояние и журнал вне Java-сервера, переживать его остановку и reboot.
- Не допускать повторного запуска и параллельных установок.
- После перезагрузки определять **фактический** результат установки, а не считать успехом простой возврат сервера.
- При ошибке показывать понятное сообщение, сохранять диагностику и обеспечивать штатный rollback установщика.

## 6. Доступ и безопасность

- Просмотр версии и проверка обновлений — во всех режимах.
- Запуск установки — **только в исследовательском/инженерном режиме**.
- При активном эксперименте установка запрещена.
- Не устанавливать обновления автоматически в фоне: только после явного подтверждения.

## 7. Совместимость

- Сохранить все существующие функции страницы «Информация».
- Не ломать старые установки без WB-метаданных.
- Не нарушать UI, API, прошивку, архивы и штатную установку.
- Не менять сборку/публикацию GitHub Releases без необходимости.
- Первый выпуск с новой функцией устанавливается обычным способом через `.wbpkg`; следующие — из UI.

## 8. Тесты

Покрыть: чтение локальной версии, сравнение релизов, недоступность GitHub/сети, повреждённый или неподходящий пакет, нехватку места, активный эксперимент, повторное нажатие, остановку Java-сервера, восстановление статуса после перезагрузки, ошибку установки и rollback.

Проверить полный сценарий на реальном Raspberry Pi 5 + ESP32-S3.

## 9. Критерии готовности

Пользователь открывает «Информация», видит WB-версию, проверяет релиз, читает изменения, подтверждает установку, видит ход операции и после перезагрузки — новую **фактически установленную** версию. Всё без SSH.

## 10. Порядок будущей реализации

Сначала изучить существующие реализации во всех трёх репозиториях, переиспользовать имеющиеся API и механизмы режима/активного эксперимента. Добавить тесты и документацию. **Не выпускать автоматически** релизы компонентов или общий `.wbpkg`; отдельно согласовать выпуск. Не объявлять задачу завершённой до проверки на приборе.
